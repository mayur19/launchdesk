# Risk register

Likelihood and impact: Low / Medium / High. Reviewed at each milestone boundary.

| ID   | Risk                                                                            | Likelihood | Impact | Mitigation                                                                                                                              | Owner role        | Status                                                         |
| ---- | ------------------------------------------------------------------------------- | ---------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | -------------------------------------------------------------- |
| R-01 | Customer user sees provider-internal data through a forgotten field or endpoint | Medium     | High   | Separate `/customer/*` API tree and DTOs (ADR-0013); SQL-level visibility filters; isolation regression suite over every route (LD-063) | Tech lead         | Open (mitigation designed; binding and 403 guards implemented) |
| R-02 | Cross-tenant data leak through an unscoped query                                | Low        | High   | Tenant id first parameter in repositories; composite FKs; 404 tests per endpoint (ADR-0003)                                             | Tech lead         | Mitigated for customers; open for pending modules              |
| R-03 | Concurrent dependency edits create a cycle                                      | Low        | Medium | Project row lock + pure graph validation inside one transaction (ADR-0014, LD-030)                                                      | Backend engineer  | Open                                                           |
| R-04 | Health status disputed by users ("why is this red?")                            | Medium     | Medium | Rule-based health with reasons and record ids (ADR-0016); reasons shown in UI (LD-027, LD-049)                                          | Product owner     | Mitigated in domain; UI pending                                |
| R-05 | Template edits unexpectedly change running projects                             | Low        | High   | Snapshot instantiation (ADR-0015); L-03 E2E test                                                                                        | Backend engineer  | Open (design accepted)                                         |
| R-06 | Milestone approvals edited after the fact                                       | Low        | High   | Append-only review rounds, write-once decision columns, audit (ADR-0017)                                                                | Backend engineer  | Open                                                           |
| R-07 | Malicious file uploaded and downloaded by another party                         | Medium     | Medium | Allow-list, size limit, attachment disposition, nosniff, no execution; UI caveat; scanning post-MVP (ADR-0011)                          | Security champion | Open                                                           |
| R-08 | Time zone errors mark tasks overdue on the wrong day                            | Medium     | Medium | Local dates per project time zone; injected clock; DST tests (`local-date.test.ts`)                                                     | Backend engineer  | Mitigated in domain                                            |
| R-09 | Scope creep beyond the MVP (integrations, Kanban polish)                        | High       | Medium | Explicit cut order in roadmap; PRD non-goals; backlog review per milestone                                                              | Product owner     | Open                                                           |
| R-10 | Estimates too optimistic for M2 (largest milestone)                             | Medium     | Medium | Domain logic already built (LD-020, LD-021); split tickets <= 6 h; re-plan after M1                                                     | Project lead      | Open                                                           |
| R-11 | Local-only file storage limits horizontal scaling                               | Medium     | Low    | Storage behind a service interface; object storage swap documented (ADR-0011)                                                           | Tech lead         | Accepted                                                       |
| R-12 | Single-role-per-user model blocks users who act for two customers               | Medium     | Low    | Multi-membership ticket LD-012; API split unaffected                                                                                    | Tech lead         | Accepted for MVP                                               |
